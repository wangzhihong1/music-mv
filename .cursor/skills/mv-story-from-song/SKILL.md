# MV 故事编剧

写故事时你就是一个编剧大师。

只需要拿歌的主题去发展故事，场景中不一定有人，也不一定只有一个主角，都是多元化的。

不要一上来写分镜表、时间码或 H3 提示词。下游分镜由 `mv-script-from-story` 负责。

本技能只借公开技能里的**方法**（先锁锚点、先写总谱、歌词四种对位），不搬别人的默认时长、关键帧流程、模型语法或整份 prompt。本仓库的流程、模板和 `song.json` 字段优先。

动手前读 [craft.md](craft.md)。

## 启动门槛

遵循 `music-mv/AGENTS.md` 歌词完成后的强制流程：

1. 用户没有明确要 MV 故事时，只询问，不写故事。
2. 必须先读当前歌曲的 `01-brief.md`、`03-lyrics.md`、`song.json`（`coreStatement`、`sections`、`prompts`）。
3. 用户指定短片范围（例如只拍第一段副歌）时，按该范围写故事，并在文首标明。

## 工作顺序

写正文前，先在内部完成这四步；不要把工作笔记原样贴给用户。

### 1. 解码这首歌

从现有档案抽出，不得改写用户原意：

- 核心创作句 / `coreStatement`
- 写给谁、关于什么、听完什么感受、记住什么
- 情绪曲线与歌曲结构
- Hook、必须保留的意象和关键句
- 必须避免的偏离（歌曲没写的车祸、出轨、死亡、励志翻盘等，一律不擅自加入）

### 2. 锁五个锚点

全片只锁一套，后面五段都围着它转：

| 锚点 | 要求 |
| --- | --- |
| 一种核心情绪 | 听完这首歌真正剩下的感觉，不是风格标签 |
| 一个视觉母题 | 可反复出现并发生形态变化（合照、一盏灯、一条未发送息） |
| 一件锚点道具 | 手能碰到、镜头能停住 |
| 一次破裂 | 人物理解、选择或关系改变的那一下 |
| 一个最终画面 | 观众离开时仍记得的最后一帧 |

五个锚点对不上这首歌，就还没准备好写故事。

### 3. 用主题长出世界，而不是配歌词、也不是拴死一个人

只需要拿歌的主题去发展故事。先问这首歌的世界是什么、怀念或冲突落在何处，再发明可拍摄的场景。坏故事是歌词逐句插画，也是全片跟拍同一个主角。

地点要少，而且彼此相连。先定这支片子里观众能走过去的那几个地方，事情都发生在这些地方里。人可以换，也可以没人；地方不要每场各换一处。坏故事是每段画面都像另一个村子。

场景默认多元化：

- 可以没人：空路、空田、空房间、只剩物件和天气
- 可以是不同的人：孩子、长辈、路人、一闪而过的脸，不必贯穿全片
- 可以有一个或几个反复出现的人，但这不是默认格式
- 主体可以是地方、日子、群像或空景

对歌词只在少数节点对准（Hook、不可替代的专有信息、桥段点题）。多数场景跟着主题走，不对词。

对歌词意象若要用，全片选一种对位，不要混成逐句还原：

- **直译**：词里的物件真的在场，但要变成世界的一部分，不能当分镜清单
- **概念**：拍主题的生活等价物
- **隐喻**：用另一套可拍摄系统承载主题
- **对位**：画面与歌词故意相反，用来揭示潜台词

演唱或对口型只作情绪强化，不能取代主线。每一场至少推进主题：世界状态怎么变、怀念落在哪、观众理解如何改。

### 4. 先定设定，再写成一篇叙事

概要和开场、发展、转折、高潮、结尾只是故事设定，用来锁核心。它们不能代替故事。

正文必须是一篇按时间写下来的叙事文章：有场景、有事件、有因果，读完能看见事情怎么发生。核心（主题、破裂、最终画面）写完后保持不变；具体场面为这个核心服务，不为歌词逐句服务。不一定有单一人物弧。用可见事物写情绪，禁止空形容词。

| 阶段 | 叙事任务 |
| --- | --- |
| 开场 | 主题所在的世界进场（可以是空景） |
| 发展 | 日子、景物或众人让主题开始变化 |
| 转折 | 观众对这个世界的理解被改写 |
| 高潮 | 对准歌曲最强释放，完成破裂 |
| 结尾 | 落点呼应核心创作句；最终画面落地 |

## 交付

按 `music-mv/templates/song/06-mv-story.md` 写入当前歌曲的 `06-mv-story.md`，并同步 `song.json`：

- `mvStory.summary` ← 一句话故事（设定）
- `mvStory.opening` / `development` / `turningPoint` / `climax` / `ending` ← 五段设定，各用几句锁功能，不代替正文
- `mvStory.narrative` ← 完整叙事文章
- `mvWorkflow.storyStatus`：提交审阅时为 `draft`；用户明确确认、定稿或满意后才改为 `confirmed`

聊天里先把这篇叙事读给用户。一句话和五段可以放在文前作设定，不能只交设定。

## 停住

提交后等待审阅。未确认不得进入分镜。确认后询问：`这个 MV 故事已经确认。需要我继续把它拆分为可执行的 MV 脚本吗？`

## 自检

- [ ] 故事离开这首歌就站不住，不能套到另一首歌上
- [ ] 五个锚点齐全，母题在五段里有变化
- [ ] 从主题长出，不是歌词一对一，也不是单人跟拍全片
- [ ] 正文是一篇完整叙事；概要和五段只是设定
- [ ] 地点少而相连，事情发生在这些地方里，不是每场各换一处
- [ ] 场景允许空景、多人、群像；不硬造唯一主角
- [ ] 没有为了好看加入歌曲未授权的灾难或狗血
- [ ] Markdown 与 `song.json` 一致
- [ ] 已标明未确认，并等待用户
