# 音乐创作项目

这个项目用于统一管理歌曲灵感、音乐风格、歌词、中英文提示词、MV 创作和最终成品。

## 单曲创作工作台

项目包含一个 Vue 3 Web 页面，用于集中呈现歌曲核心信息、歌词、风格提示词和 MV 脚本。

```bash
npm install
npm run dev
```

页面支持：

- 一键复制完整歌词
- 一键复制完整提示词或单个提示词字段
- 中英文提示词切换
- 点击歌词段落联动对应 MV 镜头
- 按时间码对照歌词和 MV 脚本
- 桌面与手机响应式布局

页面数据完全来自本地歌曲目录。每首歌曲文件夹中的 `song.json` 是工作台数据源；Agent 更新歌词、提示词或 MV 脚本时，会同时更新该文件。开发服务会扫描 `02-创作中` 和 `03-已完成`，文件变化后页面自动刷新。

MV 故事确认且用户同意拆分脚本后，必须先询问并等待用户确认歌曲最终总时长。不得使用估算时长直接写脚本。每个分镜必须为 1–10 秒；完整脚本从 `00:00` 连续覆盖到歌曲结束，不得留空档、重叠或超时，并完整呈现开场、发展、转折、高潮和结尾。运行 `npm run validate:songs` 可单独检查，生产构建也会自动执行该检查。

## 目录说明

| 目录 | 用途 |
| --- | --- |
| `01-灵感池` | 记录还未正式立项的主题、句子、故事和声音想法 |
| `02-创作中` | 存放正在制作的歌曲，每首歌使用独立文件夹 |
| `03-已完成` | 存放已定稿、已发布或暂时封存的歌曲 |
| `04-公共素材` | 积累可复用的音乐风格、歌词素材和提示词 |
| `05-歌曲模板` | 新歌立项时复制使用的标准文档 |

歌曲创作的统一原则见 `创作原则.md`。

## 新建歌曲

歌名和创作描述可以先用于讨论方向，不会自动建立歌曲。只有用户明确表示开始写歌，或在 Agent 询问“方向已经比较清楚了。现在要开始写歌吗？”后明确同意，才进入正式创作并建立歌曲。

正式开始后，可以通过歌名、创作描述，或者两者一起建立歌曲。

已有歌名时：

```bash
./新建歌曲.sh "歌名"
```

只有创作描述、还没有歌名时：

```bash
./新建歌曲.sh --描述 "一首关于深夜独自开车的城市流行歌，克制、孤独，但结尾带一点希望"
```

歌名和描述都已确定时：

```bash
./新建歌曲.sh --歌名 "凌晨出口" --描述 "一首关于深夜独自开车的城市流行歌，克制、孤独，但结尾带一点希望"
```

只有描述时，系统会先使用 `未命名歌曲` 作为暂定歌名，并完整保存用户的原始描述。同一天有多首未命名作品时会自动添加编号。确定正式歌名后，可将歌曲文件夹和文档标题改为正式名称。

系统会在 `02-创作中` 下自动创建：

```text
YYYYMMDD-歌名/
├── 01-歌曲企划.md
├── 02-音乐风格.md
├── 03-歌词.md
├── 04-中英文提示词.md
├── 05-制作记录.md
├── 06-MV故事.md
├── 07-MV脚本.md
├── 08-完成检查.md
└── 参考素材/
```

例如：`20260821-风经过的地方`。

## 标准流程

1. 用户先与 Agent 讨论想法；歌名、描述和完整需求都只作为讨论内容，不自动触发创作。
2. 当方向足够清楚时，Agent 主动询问：`方向已经比较清楚了。现在要开始写歌吗？`
3. 用户明确表示开始或明确同意后，在 `01-灵感池` 记录最初想法，并用歌名、描述或两者一起建立歌曲文件夹。
4. 保留用户原始描述，并从中整理主题、听众、情绪、风格、语言、场景和叙事视角。
5. 回答歌曲核心四问：写给谁、关于什么、希望听众产生什么感受、最想让人记住什么。
6. 确定音乐风格，再写歌词和中英文提示词。
7. 歌词完成后，主动询问用户是否需要创作与歌曲贴切的 MV 故事。
8. 用户需要时创作并修改 MV 故事，直到用户明确确认故事。
9. 故事确认后，主动询问用户是否需要将故事拆分为 MV 脚本。
10. 只有用户同意后才拆分 MV 脚本；用户不需要时保留故事即可。
11. 每次生成、试听和修改都写入制作记录。
12. 通过完成检查后，将整个歌曲文件夹移到 `03-已完成`。

## MV 交互规则

- 歌词尚未完成时，不提前推动 MV 故事阶段。
- 歌词完成后必须主动询问：`歌词已经完成。需要我继续创作一个与这首歌贴切的 MV 故事吗？`
- MV 故事必须继承当前歌曲的主题、情绪、人物关系、核心意象和情绪转折，不能写成与歌曲无关的独立故事。
- 故事提出后应先让用户审阅和修改；只有用户明确表示确认、定稿或满意，才算故事确认。
- 故事确认后必须主动询问：`这个 MV 故事已经确认。需要我继续把它拆分为可执行的 MV 脚本吗？`
- 未得到用户同意前，不提前拆分镜头或编写 MV 脚本。

## 文件命名规则

- 歌曲文件夹：`YYYYMMDD-歌名`；尚无歌名时使用 `YYYYMMDD-未命名歌曲`
- 音频版本：`歌名-v01.mp3`、`歌名-v02.wav`
- 歌词版本：主要版本写在 `03-歌词.md`，大改前可另存为 `歌词-v01.md`
- 封面文件：`歌名-封面-v01.png`
- 日期采用歌曲正式立项当天的年月日；后续修改不更改文件夹日期
